## 核心定位：它到底是什么？

**Human-Centered Feature Design** 是一个**“在特定情境下，推理最适合的用户行为与产品解法”**的心理机制推理引擎。

一句话来说，它用来**帮你理清在特定情境下，用户到底真正需要什么**。这种需要具备跨尺度的穿透力：
* **大至系统级功能设计**：确定功能的心理契约、界定价值交付形式（到底是在帮用户卸下心理负担，还是在增加新的消化压力）；
* **小至单点交互设计**：推导一个具体组件在注意力流转中的细微状态（一个展开卡片在用户切走又切回时，何时该保留状态、何时该静默复位）。

## 边界与防误用（Anti-Misuse：它不是什么）

为了保证框架的纯粹性，必须清晰界定它的使用边界：

* ❌ **它绝不是**：
  * 凭空脑暴商业模式、凭空发明新功能的点子生成器；
  * 为了虚荣指标去搞签到、打卡、积分、弹窗骚扰等“制造虚假粘性”的增长套路。
* ✅ **它的核心价值在于**：
  * **去检验和打磨一个已经确定要做的功能，保证它在心理机制上是真的在满足用户真实需求，而不是团队自我感觉良好的“伪设计”与虚假粘性。**

## 具体使用场景（何时使用本框架？）

当你或你的 AI Agent 处于以下情境时，应当调用本框架进行深度推导：

### 场景 1：当你要给一个核心功能定性、界定它与用户之间的“核心契约”时
* **典型情景**：功能方向已经确定，但在落地构思时容易滑向“堆砌分类、堆积库存”的惯性，反而给特定时空下的用户增加了认知负荷与挑选压力。
* **真实案例联动**：  
  👉 **[案例 01：话题卡重构——从类目罗列到契约对齐](#案例-01话题卡重构内容契约与处境的对齐)**  
  *用户在固定练习场景下需要的不是海量分类带来的选择焦虑，而是一张能即开即练、明确交付预期的低阻力契约卡。*

### 场景 2：当你要推导微观交互在特定情境下的状态流转与边界时
* **典型情景**：在设计一个具体的交互组件（如展开/收起、暂存态、模态浮层、多任务状态）时，不确定界面状态在用户切后台、离开视口或完成单次任务后何时该保留、何时该重置。
* **真实案例联动**：  
  👉 **[案例 02：动态阅读状态——展开与收起的三重处境边界](#案例-02动态阅读状态三重处境边界的拆解)**  
  *将卡片展开准确定位为用户的“临时注意力焦点”，推导在何种真实情境下系统应静默复位，绝不给再次进入的用户残留视觉与心理负担。*

### 场景 3：当你需要审查一个已有设计、去伪存真剔除“团队自嗨”时
* **典型情景**：一个功能在交互稿里看起来流程完整、界面炫丽，但在用户真实生活里却被反感或迅速弃用。用本框架的三大黄金法则穿透表象，审视这个功能到底是在帮用户重归平衡，还是在用冗余机制绑架用户精力。

## 快速上手与 AI Coding Agent 集成

### 为什么 AI Coding Agent（Claude Code / Cursor / Antigravity）极度需要它？
当前的 LLM 在写代码和设计 UI 时，极其容易掉入“平庸套路”的陷阱：默认建议做红点提醒、签到弹窗、死板的步进器或过度复杂的操作流。把本 Skill 注入 Agent 后，能**赋予 AI 顶级产品经理的“克制审美与情境推理能力”**，让 AI 在写代码前先自检心理机制。

### 1. 作为 Agent Skill 安装（1 分钟跑通）

#### 方式 A：Claude Code 全局安装
```bash
# 克隆仓库并软链接到 Claude Code skills 目录
git clone https://github.com/your-username/human-centered-feature-design.git
mkdir -p ~/.config/skills/human-centered-feature-design
cp human-centered-feature-design/SKILL_zh.md ~/.config/skills/human-centered-feature-design/SKILL.md
```

#### 方式 B：Cursor / Windsurf / Antigravity 项目注入
将本仓库中的 `SKILL_zh.md`（或英文版 `SKILL.md`）直接拷贝至项目的 `.cursorrules`、`.rules` 或 `.github/agent-skills/` 目录下。

### 2. 日常调用与结对推导

在日常与 AI 结对编程或方案推演时，你可以直接吩咐 Agent：
> *“帮我设计这个卡片的交互方案，先用 human-centered-feature-design 诊断用户在当下情境的心理稳态和能动感，避免制造伪需求。”*  
> *“为什么用户在这个界面容易放弃？用本框架的六大能力感环节做一次漏洞排查。”*  
> *“用框架的三大黄金检验原则，审查当前 PR 的交互细节。”*

## 真实业务实战复盘 (Production Retrospectives)

本框架附带了两篇真实商业产品（AI 语言沉浸应用）的设计复盘，完整展示了情境推理如何解决实际的烂摊子：

### 案例 01：话题卡重构——内容契约与处境的对齐
> 完整复盘文档：[`examples/01-talk-about-today-cards.md`](examples/01-talk-about-today-cards.md)

* **起因与伪设计**：团队原本以为“今日话题”卡片点击率低是卡片太丑、配图不够吸引人，准备做更多视觉动效和海量分类推荐。
* **情境心理诊断**：
  1. 用户在“固定练习时段”打开 App，其动机已经非常充沛，无需被额外刺激；
  2. 真正的阻碍是**决策阻力**——面对海量类目（电影、科技、旅游），用户不知道“点进去要聊多久、要聊什么、能不能聊完”；
  3. 卡片入口承诺“聊聊昨天的梦”，点击进去交付的却是一个宽泛的分类列表，造成了严重的**契约断裂**。
* **重构落地**：从“分类类目”重构成“明确契约卡”；将静态库存逻辑改为“消化欠账”逻辑；入口承诺精确对齐交付，决策摩擦直接归零。

---

### 案例 02：动态阅读状态——三重处境边界的拆解
> 完整复盘文档：[`examples/02-expand-collapse-state.md`](examples/02-expand-collapse-state.md)

* **起因与伪设计**：为了让用户“完整沉浸阅读”，团队做了卡片点击全量展开，但发现状态一旦持久保留，用户再次回到主屏时面对一堆展开的长卡片极度烦躁；而若机械定时收起，又会切断用户的阅读心流。
* **情境心理诊断**：
  1. 展开卡片不是内容的固有持久状态，而是用户在特定视口下的**“临时注意力焦点”**；
  2. 当用户的注意力转移（滑出屏幕、切换 Tab、锁屏离开），这一临时注意力状态已自然消亡；继续保留展开不仅不是贴心，反而制造了界面杂乱与认知欠账。
* **重构落地**：推导出严密的三重处境边界：
  * *视口内微中断*（接电话、短暂停顿）➔ **坚决保护心流，不收起**；
  * *完全离开视口*（滑出屏幕范围）➔ **静默平滑复位，无视觉突变**；
  * *离开当前模块*（切换 Tab 或退出页面）➔ **隐形重置，恢复初始秩序**。

## 底层世界观：为什么这套推理行之有效？

所有的情境推理与功能决策，均立足于关于人类心理特质的三个不可动摇的核心假设：

```
                    ┌────────────────────────────────────────┐
                    │            真实处境中的人              │
                    │   (有限的注意力资源、生物节律与心智负荷)    │
                    └───────────────────┬────────────────────┘
                                        │
                                   偏离心理稳态
                                        │
                                        ▼
                    ┌────────────────────────────────────────┐
                    │          作为需求出口的产品            │
                    ├────────────────────────────────────────┤
                    │  • 动机设计：匹配需求拓扑类型          │
                    │  • 能力感设计：交互全链路六大环节      │
                    │  • 触发设计：FBM 处境缺口精准识别       │
                    └───────────────────┬────────────────────┘
                                        │
                                        ▼
                       重归身心平衡 · 用户感知到自我掌控
```

1. **人是自我调节的系统（心理稳态 Homeostasis）**  
   需求产生于个体偏离稳态（匮乏或溢出）。产品无法凭空制造渴望，只能成为帮助用户排解张力、重归平衡的顺畅管道。
2. **人认知上脆弱，但渴望感觉有能力（主观能动感 Agency）**  
   系统的最高职责是隐形地托住用户，同时把所有成就与掌控的功劳还给用户。**好的系统是隐形的。**
3. **人永远活在处境里（处境感知 Situated Context）**  
   任何功能信号或通知能否生效，完全取决于它与用户当下所处的空间、时间与认知负荷的匹配度。**产品的影响力是借来的，不是拥有的。**

## 核心设计推导架构

框架引导设计者从三个系统性维度展开完整推导：

### 模块一：动机设计——让功能成为需求的自然出口
| 需求类型 | 特征 | 场景示例 | 留存机制 |
|---|---|---|---|
| **离散型** | 完成标准客观明确，完成后动机自然终止。 | 查天气、翻译、记账 | **用结果换信任**：每次精准交付，建立下一次失衡时的首选反射。 |
| **连续型** | 没有客观终止点，动机随处境浮现与消退。 | 好奇心、表达欲、倾听 | **用延续换粘性**：在平衡点埋下微弱未完成感，管理“消化欠账”而非堆积“静态库存”。 |
| **混合型** | 有阶段里程碑，但成长无上限。 | 语言学习、写作、编程 | 兼顾确定性的结果交付与持续进阶的良性张力。 |

### 模块二：能力感设计——交互六大环节的尊严沉淀
能力感并非来自空洞的系统弹窗表扬，而是六大环节严丝合缝的顺畅体验：
1. **感知**：让模糊感知具象化（让用户明确意识到：“对，这就是我当下的出口”）。
2. **搜寻与关联**：信息架构贴合用户既有心智，降至最低认知阻力。
3. **决策**：核心路径默认减去多余决策；不可逆操作提供充分安全感。
4. **行为**：零延迟的物理响应，保护交互连续性不被意外切断。
5. **结果评价**：**严格对齐承诺与交付**；结果归因于“我做到了”而非算法炫技。
6. **习惯形成**：核心路径不做破坏性打扰；在满足感高位提前就绪下一阶段入口。

### 模块三：触发设计——在真实的处境中无感就绪
* **解构真实处境**：物理空间约束、时间生理基线、心理认知余量。
* **用 FBM 识别行为缺口**：精准判断用户卡壳到底是因为缺动机、缺能力（认知摩擦）、还是缺时机？
* **营造产品处境**：在缺口处精准提供支架，彻底杜绝无差别机械推送噪音。

## 上线前审查：三条黄金检验原则

在确定任何功能原型或交互决策前，用这三个问题审视自检：

1. **这个设计是在帮用户回到平衡，还是在制造新的焦虑？**
2. **这个设计让用户感觉是自己在掌控，还是被系统牵着走？**
3. **这个设计嵌入了用户的真实处境，还是在制造脱离处境的噪音？**

*三个问题都能笃定回答“是前者”，设计才是真正合乎人性的。*
