## 概述

**Human-Centered Feature Design** 是一个独立、普适的产品功能设计框架，也是一份可以直接注入 AI 编程助手（Claude Code、Antigravity、Cursor 等）的 Agent Skill。

在现代软件开发中，功能往往不是因为“不够用力”而陷入停滞，而是由于出发点的错配：**在用户不缺动机的处境里过度制造动机，却忽视了用户在每个交互环节真正需要的能力感与掌控感。**

本框架旨在将产品功能的决策原点，从冰冷的“漏斗指标”重新拉回“真实的人性规律”。它既可以作为产品经理、设计师和独立开发者日常推演功能的设计底座，也可以作为 Agent Skill 在 AI 辅助设计时提供深度批判与决策支撑。

## 底层世界观（设计的起点）

本框架的所有推导与评判，均建立在关于人类心理特质的三个核心假设之上：

```
                    ┌────────────────────────────────────────┐
                    │            真实处境中的人              │
                    │   (有限的注意力资源、生物节律与心智负荷)    │
                    └───────────────────┬────────────────────┘
                                        │
                                   偏离心理稳态
                                        │
                                        ▼
                    ┌────────────────────────────────────────┐
                    │          作为需求出口的产品            │
                    ├────────────────────────────────────────┤
                    │  • 动机设计：匹配需求拓扑类型          │
                    │  • 能力感设计：交互全链路六大环节      │
                    │  • 触发设计：FBM 处境缺口精准识别       │
                    └───────────────────┬────────────────────┘
                                        │
                                        ▼
                       重归身心平衡 · 用户感知到自我掌控
```

1. **人是自我调节的系统（心理稳态 Homeostasis）**  
   需求来自个体偏离稳态（匮乏或溢出）。产品无法凭空制造渴望，只能成为帮助用户排解张力、重归平衡的顺畅管道。
2. **人认知上脆弱，但渴望感觉有能力（主观能动感 Agency）**  
   系统的最高职责是隐形地托住用户，同时把所有成就与掌控的功劳还给用户。**好的系统是隐形的。**
3. **人永远活在处境里（处境感知 Situated Context）**  
   任何功能信号或通知能否生效，完全取决于它与用户当下所处的空间、时间与认知负荷的匹配度。**产品的影响力是借来的，不是拥有的。**

## 核心设计架构

框架引导设计者从三个系统性维度展开完整推导：

### 模块一：动机设计——让功能成为需求的自然出口

| 需求类型 | 特征 | 例子 | 留住用户的方式 |
|---|---|---|---|
| **离散型** | 需求完成可被客观验证，完成后动机自然终止。 | 查天气、翻译、导航 | **用结果换信任**：每次使用达到或超出预期，建立下一次需求浮现时的第一反射。 |
| **连续型** | 没有外部标准判断完成，动机随时浮现与消退。 | 好奇心、表达欲、陪伴感 | **用延续换粘性**：满足当下的同时埋下轻微未完成感，在适应钝化前主动就绪新入口。 |
| **混合型** | 有客观阶段标准，但上限可以不断延展。 | 学习、写作、健身 | 兼顾确定性的结果交付与持续消化的未完成张力（欠账 vs 静态库存）。 |

### 模块二：能力感设计——交互六大环节的尊严沉淀
能力感并非来自空洞的赞美，而是交互全流程严丝合缝的自然沉淀：
1. **感知**：让模糊感知具象化（让用户明确感知到：“对，这就是我当下的出口”）。
2. **搜寻与关联**：信息架构贴合用户既有的心智模型，最小化无谓的认知消耗。
3. **决策**：核心路径默认减少决策摩擦；高代价、不确定、不可逆的操作提供充分的安全感与回退机制。
4. **行为**：零延迟的状态回应，保护操作连续性不被意外切断。
5. **结果评价**：**严格对齐承诺与交付**（切忌在入口卡片承诺具体句子，点击后交付抽象分类）；结果归因于“我做到了”而非算法炫技。
6. **习惯形成**：核心路径只做减法不做破坏性变动；在用户满足感高位提前就绪叠加路径。

### 模块三：触发设计——在正确的处境里自然激活
* **解构真实处境**：物理空间（注意力资源与操作约束）、时间窗口（生理基线）、心理状态（认知余量）。
* **用 FBM 识别行为缺口**：判断当下缺口究竟在动机、能力感（认知阻力）、还是时机？
* **营造产品处境**：针对真实缺口调节信息密度、节奏与氛围，杜绝盲目机械式重复推送噪音。

## 上线前审查：三条黄金检验原则

在敲定任何功能方案或交互细节前，用这三个问题审视：

1. **这个设计是在帮用户回到平衡，还是在制造新的焦虑？**
2. **这个设计让用户感觉是自己在掌控，还是被系统牵着走？**
3. **这个设计嵌入了用户的真实处境，还是在制造脱离处境的噪音？**

*三个问题都能回答“是前者”，设计才是真正合乎人性的。*

## 真实业务实战参考 (`examples/`)

为展现这套通用框架在具体业务场景中的推导过程，本仓库收录了在真实产品打磨过程中的两篇设计复盘：

* **[案例 01：话题卡重构——内容契约与处境的对齐](examples/01-talk-about-today-cards.md)**  
  *场景*：英语学习 App 的今日话题发现卡片，团队原本以为是排版与视觉问题。  
  *推导*：诊断出内容契约断裂（卡片承诺一句具体人话，点击却交付抽象大类）与处境错配（固定练习时段用户动机本已充分，真正缺的是“选哪个、练多久、产出什么”的决策依据）。
* **[案例 02：动态阅读状态——三重处境边界的拆解](examples/02-expand-collapse-state.md)**  
  *场景*：长文卡片展开阅读后的自动收起机制。  
  *推导*：明确展开是“临时的阅读注意力状态”而非持久内容状态，清晰划分出完全离开视口（屏幕外静默收起）、离开整页（静默重置）、短暂中断（保护心流坚决不收起）的三重处境。

## 使用与集成方式

### 规范文件
- **`SKILL_zh.md`**：中文完整规范，100% 保留作者原汁原味的深度与文字体系。
- **`SKILL.md`**：地道的英文规范文件，适合通用国际化 AI 工作流。

### 集成到 AI Coding Agent (Claude Code / Antigravity / Cursor)

```bash
# 复制中文版或英文版到全局 Skills 目录
mkdir -p ~/.config/skills/human-centered-feature-design
cp SKILL_zh.md ~/.config/skills/human-centered-feature-design/SKILL.md
```

在日常对话中，你可以直接让 AI 运用该框架：
> “帮我推演这个功能的交互方案……”  
> “为什么用户在这个页面容易流失？用 human-centered-feature-design 诊断一下。”  
> “请按三个底层假设和六大环节，评审这个界面的设计决策。”
