<div align="center">
  <h3>以人为中心的产品功能设计</h3>
</div>


> *“人不是产品的变量，产品才是人的变量。需求来自偏离平衡，产品无法凭空制造渴望，只能成为恢复稳态的出口。”*

**以人为中心的功能设计 (Human-Centered Feature Design)** 是一套**让功能重归人的平衡，而非制造虚假动机**的情境推理框架。它从宏观功能契约深入到微观交互边界，严密推导用户在具体处境下的真实心理机制，检验并打磨方案——确保功能真正契合现实需求，坚决剔除团队自嗨与虚假粘性。

---

## 使用时机

任何一个产品功能的落地，最终都会归结为两个维度的决策：向用户呈现什么数据，以及如何与这些数据交互。当你面对一段模糊的功能需求时，你可以唤起这个 Skill 来帮你解答两个核心问题：

1. **数据层面 (Data)**：剥离虚荣指标与伪需求，前端究竟该向用户展示哪些真正能降低“决策摩擦”的数据？
2. **交互层面 (Interaction)**：打破机器式的僵硬逻辑，怎样的状态流转边界才符合人类的心流与直觉？

以下是它基于真实商业项目（详见 `examples/`）的思考方式：

### 案例一：数据维度的设计（以“每日话题卡片”为例）
> **场景需求：设计“今日话题”卡片列表，通过展示话题吸引用户练习。**
> 
> **Before:**
> 系统直接向前端透传了原始数据。卡片上包含了与用户当前操作关联性较弱的统计指标（如 `46 pops`、`+12 more moments`），并平铺了用户过往零散的输入记录。由于未对信息的呈现优先级进行限制，界面产生了较重的认知冗余。
> 
> **After:**
> **1. 诊断**：当前的原始数据流无法协助用户建立具体的行动预期。
> **2. 数据结构收敛**：剔除全局统计指标，重构底层数据结构。
> **最终呈现**：将用户的历史活动（Activity）统一聚合。用个人的进度状态标记（如“从未开口练过”、“3天前练过”）替代全局点击数，将系统的静态库存，转化为基于个人进度的“待消化清单”。

### 案例二：交互维度的设计（以“长文卡片的展开状态”为例）
> **场景需求：在阅读流中，卡片点击后会“展开”全文。产品要求：“用户离开当前内容时，自动收起卡片”。**
> 
> **Before:**
> 将“离开内容”直接等同于“离开页面 (Tab)”。在列表内上下滑动时，系统未做自动收起，理由是“担心用户滑回原位置时发现状态改变”。结果导致多展开几张卡片后，列表不断拉长，屏幕被已阅读的信息持续占据。
> 
> **After:**
> **1. 状态分析**：推演出“展开阅读”并不属于卡片持久的数据属性，而是用户局部的临时专注状态。
> **2. 划定边界**：基于该状态的生命周期，将规则细分为三个处境边界：
>    - *视窗内的局部交互（如软键盘升起）* ➔ **维持展开状态，不介入干预**。
>    - *卡片完全滑出可视区域* ➔ **在屏幕外静默收起，无动画过渡**。用户返回原位置时，界面已恢复为初始的默认列表结构。
>    - *切换页面或 Tab* ➔ **触发全局状态重置**。

## 安装 (Install)

这是一个短小精悍的独立 Skill。你可以通过三种最轻量的方式使用它：

### 1. 手动使用
直接下载 [`SKILL_zh.md`](SKILL_zh.md)（或英文版 [`SKILL.md`](../SKILL.md)），上传至 Claude.ai Project 知识库、Cursor/Windsurf 规则配置（如 `.cursorrules`），或直接粘贴进任意 AI 对话框中。

### 2. 命令行安装到本地共享 Skill 目录
通过单行命令直接布局到本地 Coding Agent 的全局技能库：
```bash
git clone https://github.com/LillyLiuJun/human-centered-feature-design.git ~/.config/skills/human-centered-feature-design
```

### 3. 让你的 Agent 自动安装
在终端或对话中直接给你的 Coding Agent 发送提示词：
```text
帮我安装并启用这个 skill：https://github.com/LillyLiuJun/human-centered-feature-design
```

## 底层哲学 (Philosophy)

本框架的一切情境推演建立在一个根本认知之上：**产品是帮人重归平衡的工具，而非收割人类注意力的机器。**

```
处境中的人（产生失衡） ──► 产品作为隐形泄压阀 ──► 重归生理与心理稳态 · 沉淀真实掌控感
```

这一底层哲学在工程实践中具体拆解为三大支柱：

1. **系统稳态高于虚假动机 (Homeostasis)**：需求源于人生理与心理偏离平衡的张力。产品无法凭空制造渴望，只能成为离散任务或连续心流的顺畅出口（管理“消化欠账”，而非堆砌“静态库存”）。
2. **主观能动高于系统操纵 (Agency)**：人认知脆弱但渴望掌控。系统在感知、搜索、决策、行为、评价与习惯六大触点上提供隐形支架，并把所有成就归功于用户。**好的系统永远是安静的。**
3. **处境感知高于机械触发 (Context)**：产品的影响力是借来的，完全取决于与真实空间、生理节律与认知余量的匹配度。通过行为设计模型精准诊断能力与时机缺口，杜绝无差别的机械红点与弹窗轰炸。

### 三条黄金检验原则 (The Three Litmus Tests)
在敲定任何功能原型或交互细节前，用这三个问题终审自检：
* **这个设计是在帮用户回到平衡，还是在制造新的焦虑？**
* **这个设计让用户感觉是自己在掌控，还是被系统机制牵着走？**
* **这个设计无感嵌入了用户的真实处境，还是在制造脱离处境的噪音？**
